```
├── images/                 # 术语配图

├── package.json            # express/sqlite3/cors
└── README.md / UPDATE_PLAN.md
```

### 2.2 现有技术栈
- **前端**：纯原生 HTML/CSS/JS（无框架），CSS 变量主题（`--primary: #1a365d` 等）
- **后端**：Node.js + Express + SQLite（`api/server.js`，端口 3000）
- **数据**：双存储 — `data/db.json`（JSON）+ SQLite（`steel.db`）
- **部署**：GitHub Pages（`bearlove163/steel-blog`，`main` 分支）
- **自动化**：`auto_update.sh`（Tavily 搜索 → curl 抓取 → sed 注入 news.html → git push）

### 2.3 存在的问题（需在重构中解决）
1. **文章无分类**：原创文章、AI 爬取资讯、软件介绍全混在根目录，无法区分
2. **模板不统一**：存在至少 2 种文章 HTML 结构（aramco 风格 vs benfica 风格）
3. **无分支策略**：仅有 `main` 分支，直接提交，无 review/staging 流程
4. **后端未部署**：`api/server.js` 仅本地运行，GitHub Pages 无法托管 Node
5. **数据冗余**：JSON 与 SQLite 双写，易不一致
6. **无付费/工具模块**

### 3.3 网站规则（Rule）

**内容规则：**
| 模块 | 来源 | 命名规则 | 存放位置 |
|------|------|----------|----------|
| 原创文章 | 人工撰写 | `{date}-{slug}.html` | `public/articles/original/` |
| AI 资讯 | 自动爬取 | `{date}-{source}.html` | `public/news/crawled/` |
| 软件展示 | 人工录入 | `{software-slug}.html` | `public/software/` |
| 计算工具 | 人工开发 | `{tool-name}.html` | `public/tools/` |

**模板规则：**
- 所有文章统一使用 `public/articles/template.html` 作为基础模板
- 公共导航/页脚抽取为 `public/components/nav.html`、`footer.html`（用 JS `fetch` 注入）
- 公共样式抽取为 `public/assets/css/style.css`，CSS 变量保持 `--primary: #1a365d` 主题
- 文章元数据（标题/日期/分类/标签）统一登记到 `data/articles.json`

**Git 分支规则：**
| 分支 | 用途 | 保护 |
|------|------|------|
| `main` | 生产环境，火山引擎服务器拉取此分支 | 仅通过 PR 合并 |
| `dev` | 开发集成 | 可直接提交 |
| `content` | 内容更新（文章/资讯） | 自动合并到 main |

**API 规则：**
- 所有 API 前缀 `/api/`
- 统一响应格式：`{ success: boolean, data: any, error?: string }`
- 文章/资讯支持 GET 列表、GET 详情、POST 新增（需鉴权）

### ✨ 阶段 3：在线排版工具（Skill）

**目标**：网站内纯前端工具，粘贴文本 → 生成符合模板的精美 HTML。

**实现 `public/format/index.html`：**

功能流程：
1. **左侧输入区**：`<textarea>` 粘贴纯文本/Markdown 文章
2. **右侧实时预览**：`<iframe>` 或 `<div>` 实时渲染排版效果
3. **配置项**：
   - 文章标题输入框
   - 分类下拉（原创/资讯/软件介绍）
   - 标签输入（逗号分隔）
   - 日期（默认今天）
   - 主题色选择（默认 `#1a365d`）
4. **智能解析**（纯 JS）：
   - 识别 Markdown 标题 `#`/`##`/`###` → `<h1>`/`<h2>`/`<h3>`
   - 识别段落 → `<p>`
   - 识别 `**加粗**` → `<strong>`
   - 识别 `- 列表项` → `<ul><li>`
   - 识别 `> 引用` → `<blockquote>`
   - 识别图片链接 `![alt](url)` → `<img>`
   - 自动添加摘要、元信息栏
5. **导出**：
   - 「复制 HTML」按钮：复制完整文章 HTML（含 `<style>`）
   - 「下载 .html」按钮：下载可直接放入 `public/articles/original/` 的文件
   - 「上传到服务器」按钮（预留，调 `/api/articles` POST）

**技术要点**：
- 纯前端 JS，无后端依赖
- 排版样式直接复用 `public/assets/css/style.css` 的文章样式
- 导出的 HTML 自包含（内联 CSS），可直接独立访问

## 五、假设与决策

| # | 假设/决策 | 理由 |
|---|----------|------|
| 1 | 保留原生 HTML/CSS/JS，不引入框架 | 现有项目无框架，保持一致性，降低复杂度 |
| 2 | 后端继续用 Express + SQLite | 现有栈，迁移成本低 |
| 3 | 微信支付仅预留接口，不真实接入 | 无企业商户资质，且需备案域名 |
| 4 | 文章分类由文件目录区分（非数据库标签） | 便于 Git 管理与静态部署 |
| 5 | 公共导航用 JS fetch 注入 | 避免每个页面硬重复，保持纯静态可部署 |
| 6 | 排版工具纯前端实现 | 用户明确选择「网站内在线工具」 |
| 7 | 服务器部署方案由我产出，你执行 | 无服务器凭据，沙箱网络受限 |
| 8 | 现有 ~60 篇文章按命名规则自动分类 | 带日期数字的归 AI 资讯，主题名归原创 |
